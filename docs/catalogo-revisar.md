# Itens para revisar

- **Seção:** Arrays e guloso — **Bullet:** **Menor operações +1/−1 em subarray para zerar/igualar.** — **Suspeita:** a fórmula Σ max(0, d_i) = Σ|d_i|/2, com d_1 = a_1 e d_{n+1} = −a_n, resolve o custo de zerar o array; para apenas igualar, o alvo é livre e as bordas não entram da mesma forma. O "≈" do bullet mistura os dois problemas. — **Por quê:** em [1, 2, 3], zerar custa 3 operações, mas igualar em [2, 2, 2] custa 2; a fórmula completa dá 3, não 2.
- **Seção:** Arrays e guloso — **Bullet:** **LIS com restrições extras (k-LIS, LIS em subárvore, LIS pesada)** — **Suspeita:** a receita de um único BIT de máximo sobre valores comprimidos resolve LIS pesada, mas não cobre sozinha k-LIS nem LIS em subárvore. — **Por quê:** k-LIS normalmente exige uma dimensão extra para o número de violações permitidas, e LIS em subárvore exige rollback/merge ou processamento por DFS; um BIT global não restringe a subárvore.
- **Seção:** Arrays e guloso — **Bullet:** **Mex de prefixos é não decrescente; mex de todos os subarrays** — **Suspeita:** "dois ponteiros sobre contagens" não parece suficiente para o mex de todos os subarrays; ao avançar o início, remover a última ocorrência do mex pode diminuí-lo, quebrando a monotonia usual da janela. — **Por quê:** a alternativa citada, segtree sobre o último índice de cada valor, é a que lida com essas diminuições; a parte de prefixos está correta.
- **Seção:** Busca binária e otimização — **Bullet:** Sqrt inteiro e raiz k-ésima — **Suspeita:** a receita "calcule com sqrtl e corrija ±1 em um while" só se aplica à raiz quadrada; `sqrtl` não calcula raiz k-ésima. — **Por quê:** para k ≠ 2 é preciso `powl` com ajuste ou binária inteira; do modo como está, o bullet pode sugerir que sqrtl cobre os dois casos.
- **Seção:** DP — **Bullet:** Rerooting com contribuição — **Suspeita:** "guarde os momentos de f" não determina Σ f(dist) para uma f arbitrária. — **Por quê:** momentos finitos só fecham a conta se f for polinomial de grau fixo (ex.: f(d) = d²); para f arbitrária é preciso contar vértices por distância (O(n²)) ou usar outra estrutura.
- **Seção:** DP — **Bullet:** Sequência P-recursiva / equação diferencial do GF — **Suspeita:** Bell não é P-recursiva, então não se calcula em O(n) por recorrência de coeficientes polinomiais. — **Por quê:** a EGF exp(e^x−1) não é D-finite; a recorrência padrão de Bell (Bell triangle) é O(n²). O "via outra recorrência" só salva o texto se significar essa recorrência, que não é O(n).
- **Seção:** DP — **Bullet:** Passeio aleatório em linha/árvore — **Suspeita:** o parêntese "(arestas na subárvore + 1)" não bate com 2·sz − 1. — **Por quê:** se sz é o número de vértices, 2·sz − 1 = 2·(nº de arestas) + 1, não nº de arestas + 1; a fórmula está correta, o parêntese é que está errado ou ambíguo.
- **Seção:** DP — **Bullet:** LCS/edit distance com distância ≤ k pequena — **Suspeita:** "Landau–Vishkin com LCP via hash em O(n + k²)" é otimista. — **Por quê:** há O(k²) consultas de LCP e, com hash + busca binária, cada uma custa O(log n), dando O(n + k² log n); O(n + k²) só vale com LCE O(1) (suffix array + RMQ).
- **Seção:** DP — **Bullet:** DP em partições de n (√n) — **Suspeita:** "partes ≤ √n + número de partes ≤ √n" não é uma divisão disjunta dos casos. — **Por quê:** uma partição com todas as partes pequenas também tem poucas partes (ex.: 1+1+…+1), então somar as duas DPs conta casos duas vezes; o corte correto é "todas as partes ≤ B" vs "todas as partes > B", e a segunda condição é que implica poucas partes.
- **Seção:** DP — **Bullet:** **Troca de dimensão por valor da DP (generalizada).** — **Suspeita:** o exemplo "dp[k] = menor posição final com k escolhidos (LIS é isso)" não corresponde à DP clássica do LIS. — **Por quê:** o LIS indexado pelo comprimento guarda a menor cauda (valor final), não a menor posição; uma posição final menor pode ter cauda alta e não ser extensível. Exemplo: em [2, 100, 1, 2, 3], a menor posição final para comprimento 2 é a posição 2 (2,100), que não estende para 3, enquanto (1,2) termina na posição 4 e estende para 5.
- **Seção:** DP — **Bullet:** **DP sobre bits com carry.** — **Suspeita:** a alternativa "dp[bit][tightA][tightB] do mais significativo (sem carry)" não é suficiente para impor x + y = z. — **Por quê:** o bit do resultado depende do carry vindo dos bits menos significativos; processar do MSB só com tight não conhece esse carry. Para soma com limites, use carry e borrow no LSB (ou um estado que represente o carry possível), sem misturar as direções.
- **Seção:** DP — **Bullet:** **DP com transição por divisores.** — **Suspeita:** usar o crivo de múltiplos para uma "subsequência" com cada elemento dividindo o seguinte só é correto se a ordem original dos índices não importa. — **Por quê:** ordenar/iterar por valor ignora as posições; se o problema exigir uma subsequência de fato (índices crescentes), é preciso incluir a posição no estado ou usar outra estrutura, não apenas o crivo em O(V log V).
- **Seção:** Teoria dos números e divisores — **Bullet:** **Miller–Rabin determinístico.** Com as 12 primeiras bases primas (2…37) vale para n < 3,3·10²⁴, logo para todo 64 bits… — **Suspeita:** o limite está 10× alto para o conjunto de bases citado. O menor pseudoprimo forte para as 12 primeiras bases (2…37) é 318 665 857 834 031 151 167 461 ≈ 3,18·10²³; o valor ≈ 3,317·10²⁴ corresponde às 13 primeiras bases (2…41). — **Por quê:** a conclusão "logo para todo 64 bits" continua verdadeira, mas o número não corresponde ao conjunto (2…37); quem usar o limite para argumentar sobre faixas maiores pode errar por uma ordem de grandeza.
- **Seção:** Teoria dos números e divisores — **Bullet:** **Hipérbole de Dirichlet.** Σ_{ab≤n} F(a)G(b) em O(√n): Σ_{a≤A} f(a)G(n/a) + Σ_{b≤B} g(b)F(n/b) − F(A)G(B)… — **Suspeita:** o lado esquerdo deveria ser Σ_{ab≤n} f(a)g(b), não Σ F(a)G(b); F e G são os prefixos usados no lado direito. — **Por quê:** com f=g=1, Σ_{ab≤n} F(a)G(b) = Σ ab cresce ~n², enquanto a fórmula do lado direito dá Στ(n) ~ n ln n; o exemplo seguinte (Στ(i) = 2Σ⌊n/i⌋ − ⌊√n⌋²) só fecha com f(a)g(b) no lado esquerdo.
- **Seção:** Combinatória, contagem e probabilidade — **Bullet:** **Filtro de raízes da unidade.** Σ_{k ≡ r (m)} C(n, k) = (1/m)Σ_j ω^{−jr}(1+ω^j)ⁿ; versão discreta: (1+x)ⁿ mod (xᵐ − 1) por exponenciação rápida de polinômio cíclico (subconjuntos com soma ≡ r mod m). — **Suspeita:** O parêntese "subconjuntos com soma ≡ r mod m" não corresponde à fórmula. — **Por quê:** O coeficiente de x^r em (1+x)^n mod (x^m−1) soma C(n,k) para k ≡ r (mod m), isto é, conta subconjuntos pela cardinalidade k, não pela soma dos elementos. Para somas de elementos seria necessário ∏(1+x^{w_i}) mod (x^m−1); para o conjunto {1..n}, ∏_{i=1}^n (1+x^i).
- **Seção:** Combinatória, contagem e probabilidade — **Bullet:** **Matriz de transição + exponenciação** para contar caminhos de comprimento k. — **Suspeita:** A potência da matriz de adjacência conta passeios (walks), não caminhos simples. — **Por quê:** (A^k)_{ij} soma sequências de k arestas, permitindo repetir vértices; se "caminho" for usado no sentido de caminho simples, a afirmação é falsa (contar caminhos simples de comprimento k é #P-difícil). Se a intenção era passeio, basta explicitar a terminologia.
- **Seção:** Bits e XOR — **Bullet:** "Max xor de caminho / de subarray = max de pref[i]⊕pref[j]; ... (caminho; o LCA se cancela)." — **Suspeita:** a afirmação de que o LCA se cancela só vale para valores nas arestas; com valores nos vértices o xor do caminho é px[u]⊕px[v]⊕a[lca]. — **Por quê:** px[u]⊕px[v] cancela o trecho raiz–lca inclusive, removendo o valor do lca; o próprio bullet "Xor de caminho em árvore", mais abaixo na mesma seção, manda incluir a[lca] nesse caso.
- **Seção:** Bits e XOR — **Bullet:** "AND é não-crescente, OR não-decrescente ao estender. ... para cada fim, ≤ 30 pares (valor, menor início) ..." — **Suspeita:** o número de valores distintos de OR por fim pode ser 31 (o valor inicial mais até 30 mudanças de bit), não 30. — **Por quê:** OR só adiciona bits; se o primeiro valor do sufixo é 0 e os 30 bits vão sendo ligados um a um, há 31 pares (valor, menor início) distintos. Para valores de 30 bits, "≤30" é uma simplificação que pode errar por 1.
- **Seção:** Bits e XOR — **Bullet:** "Potência/caminhos no hipercubo. ... Também 'nº de maneiras de escolher k elementos (com ordem) com xor = x'." — **Suspeita:** a WHT elevada a k conta k-uplas com repetição; se "escolher k elementos" exige elementos distintos, a fórmula não vale. — **Por quê:** cada passo é uma convolução independente com o conjunto S, permitindo repetir o mesmo elemento; sem repetição seria preciso incluir no estado quais elementos já foram usados.
- **Seção:** Bits e XOR — **Bullet:** "Aresta a aresta em GF(2). ... numa árvore a solução é única, de baixo para cima." — **Suspeita:** a unicidade vale apenas quando o sistema é consistente, isto é, quando a soma das paridades pedidas é par. — **Por quê:** cada aresta contribui para a paridade de dois vértices, então a soma das paridades de todos os vértices é sempre par; se o pedido tiver soma ímpar, não existe solução.
- **Seção:** Strings — **Bullet:** **Trie + small-to-large / merge de tries.** — **Suspeita:** a complexidade declarada como O(total de nós) amortizado pode ser O(N log N). — **Por quê:** com small-to-large, um nó pode ser absorvido O(log N) vezes ao longo de merges sucessivos; sem uma análise adicional, o custo total não é necessariamente linear no número de nós.
- **Seção:** Strings — **Bullet:** **Shunting-yard.** — **Suspeita:** "menos unário ... com precedência alta" é ambíguo e pode conflitar com `^` associativo à direita. — **Por quê:** se o menos unário tiver precedência maior que `^`, `-2^2` é lido como `(-2)^2`; em muitas convenções o correto é `-(2^2)`. A precedência relativa precisa ser definida.
- **Seção:** Strings — **Bullet:** **Parsing com módulo.** — **Suspeita:** "divisão = inverso modular" só vale quando o denominador é invertível módulo p. — **Por quê:** se p não for primo ou se o denominador for múltiplo de p, o inverso não existe; a avaliação da expressão precisa garantir gcd(denominador, p) = 1.
- **Seção:** Strings — **Bullet:** **Operação troca todas as ocorrências de um símbolo.** — **Suspeita:** o mapeamento ser função é necessário, mas pode não ser suficiente para atingir o alvo. — **Por quê:** com ciclos de substituição e sem um símbolo temporário, aplicar as trocas pode sobrescrever um símbolo necessário; a suficiência depende de haver símbolo auxiliar ou de o alvo ser binário, como em CF 1807C.
- **Seção:** Grafos — **Bullet:** "Ciclo mínimo em grafo grande esparso com girth pequeno." — **Suspeita:** a condição "Se m ≥ n^{1+1/k} há ciclo de comprimento ≤ 2k" omite a constante do teorema de Bondy–Simonovits. — **Por quê:** a forma conhecida é ex(n, C_{2k}) = O(k·n^{1+1/k}), com constante que cresce com k; para k ≥ 3, m ≥ n^{1+1/k} sozinho não garante o ciclo sem o fator constante, e a BFS limitada a k só o encontra se ele existir.
- **Seção:** Grafos — **Bullet:** "Decomposição de grafo em caminhos de comprimento par/ímpar" — **Suspeita:** a construção com vértice auxiliar garante trilhas entre vértices ímpares, mas não controla a paridade do comprimento das trilhas. — **Por quê:** o circuito euleriano apenas garante usar cada aresta uma vez; o comprimento de cada trecho entre ocorrências do vértice auxiliar depende da ordem do Euler, não da paridade dos graus. O bullet promete caminhos de comprimento par/ímpar que a construção descrita não entrega.
- **Seção:** Grafos — **Bullet:** "MST com custo a\_i + a\_j (ou min/max(a\_i, a\_j))" — **Suspeita:** a parte do gcd sugere gerar arestas via múltiplos com custo d, mas o peso real da aresta é gcd(a\_i, a\_j) ≥ d; para MST mínimo isso subestima o custo e pode dar resposta errada. — **Por quê:** com valores {6, 10, 15}, os gcds são 2, 3 e 5 e a MST verdadeira custa 2 + 3 = 5; unir múltiplos de 1 com custo 1 (d = 1) dá custo 2. A varredura por divisores costuma valer para maximum spanning tree (d decrescente), não para MST mínimo como o bullet sugere.
- **Seção:** Grafos — **Bullet:** "Grafo de duas camadas (ônibus/linhas)" — **Suspeita:** "reduz arestas de O(L²) a O(L)" — o número de arestas é O(total de incidências parada-linha), não O(L). — **Por quê:** cada linha pode passar por muitas paradas; a economia é eliminar as arestas linha-linha O(L²), mas o grafo construído tem Σ|linha| arestas, que pode ser muito maior que L.
- **Seção:** Árvores — **Bullet:** HLD offline com 2 Fenwicks para "adicione x no caminho, some caminho" — **Suspeita:** a cláusula final "por contribuição do vértice × tamanho: Σ_{v em caminho} a_v = prefixos da raiz" não descreve range add + range sum e parece misturar duas técnicas distintas. — **Por quê:** prefixos da raiz resolvem point update + path sum; para "adicione x no caminho, some caminho" com HLD são necessários dois BITs por cadeia (range add/range sum) ou uma formulação offline de diferenças com soma de subárvore, e a fórmula citada não fecha nenhuma das duas.
- **Seção:** Árvores — **Bullet:** Facility location (p-mediana/p-centro) em árvore — **Suspeita:** "p-mediana: DP O(n²p) ou O(np) com Aliens" — a complexidade O(np) com Aliens parece inconsistente. — **Por quê:** o Aliens remove a dimensão p trocando-a por uma busca binária no custo (fator log), e o DP base de p-mediana costuma ser O(n²) por penalidade; a versão com Aliens não elimina o fator n² nem mantém O(np) sem hipóteses adicionais.
- **Seção:** Árvores — **Bullet:** BFS tree e dual: — **Suspeita:** "ciclo mais curto através de v = min sobre arestas (u, w) com lca(u, w) = v de d(u) + d(w) + 1 − 2·d(v)" só é exato quando a árvore está enraizada em v (ou quando os dois caminhos da árvore realmente divergem em v). — **Por quê:** com raiz arbitrária, o ciclo mais curto por v pode ter LCA acima de v e não aparecer na minimização; além disso, d(u)+d(w)+1 sem a condição de divergência pode ser um passeio fechado que não é um ciclo simples por v.
- **Seção:** Árvores — **Bullet:** Distâncias a k (todos os vértices com dist exata k) — **Suspeita:** "O(n) só com long-path decomposition" para distâncias exatas de todos os v parece incorreto; long-path resolve contagens de profundidade na subárvore em O(n), não todas as distâncias a partir de cada vértice. — **Por quê:** para todos os v e todos os d a saída é O(n²); para k fixo o DP é O(nk), e long-path não elimina esse fator sem uma estrutura adicional (por exemplo, para um único d há técnicas de DSU on tree, mas não O(n) para todos os d e todos os v).
- **Seção:** Estruturas de dados e queries — **Bullet:** "Maior subarray de xor / par com xor máximo no intervalo." — **Suspeita:** a receita "Subarray: prefix xor + trie persistente (par de prefixos)" sugere que a trie persistente responde o máximo sobre todos os pares de prefixos em [l−1, r]; ela responde apenas o melhor par com um valor fixo. — **Por quê:** o máximo de p_i ⊕ p_j com l−1 ≤ i < j ≤ r exige varrer uma das extremidades (O(comprimento · log A) por query) ou uma estrutura adicional; as contagens por nível só permitem testar um x por vez.
- **Seção:** Estruturas de dados e queries — **Bullet:** "Queries de 'intervalo cujos elementos distintos estão todos em [lo, hi]'." — **Suspeita:** a condição "intervalo [l, r] contém todas as ocorrências de v ⇔ prev(l) < l e next(r) > r" mistura duas perguntas e usa prev/next sem dizer de que posição. — **Por quê:** "todos os valores distintos de [l, r] estão em [lo, hi]" equivale a min(a[l..r]) ≥ lo e max(a[l..r]) ≤ hi; "conter todas as ocorrências de v" equivale a l ≤ first[v] e r ≥ last[v]. Nenhuma das duas vira prev(l) < l e next(r) > r como escrito.
- **Seção:** Teoria dos jogos — **Bullet:** Subtraia só quadrados / primos / potências — **Suspeita:** "se n ≤ 10⁶, é só isso" não vale para primos: |S| = π(n) ≈ n/log n, então o DP é O(n²/log n) ≈ 8·10¹⁰ para n = 10⁶; só é viável para quadrados (|S| ≈ √n) e potências (|S| ≈ log n). — **Por quê:** a complexidade O(n·|S|) é correta, mas o tamanho de S depende do conjunto; para primos ele não é pequeno.
- **Seção:** Geometria — **Bullet:** Perímetro da união de retângulos — **Suspeita:** a alternativa "ou 2×(variações)" parece incorreta ou, no mínimo, ambígua. — **Por quê:** somar |Δ comprimento coberto| ao longo do sweep em um eixo já contabiliza as bordas daquele eixo (verticais no sweep em x); repetir o procedimento no outro eixo dá as horizontais. Multiplicar as variações por 2 duplicaria o perímetro. Além disso, "abre antes de fechar" não basta quando vários eventos caem no mesmo x: é preciso agrupá-los antes de medir Δ.
- **Seção:** Geometria — **Bullet:** Rotating sweep (ordem de projeção) — **Suspeita:** a afirmação de que o rotating sweep "resolve 'maior triângulo/área em k pontos'" não é padrão e possivelmente está errada. — **Por quê:** o rotating sweep mantém a ordem de projeção e resolve consultas de ordem/k-ésimo em direções que giram; o maior triângulo é resolvido por calipers no hull (bullet seguinte) e não decorre da ordem de projeção.
- **Seção:** Geometria — **Bullet:** Minkowski e "mover o objeto" — **Suspeita:** sinal/convenção incompletos em "Colisão de polígono convexo em translação = ponto em Minkowski(A, −B)". — **Por quê:** se A é transladado pelo vetor t, há colisão com B quando t ∈ B ⊕ (−A), que é o negativo de A ⊕ (−B); a frase omite o vetor de translação e o sinal, então a igualdade literal não vale sem escolher uma convenção.
- **Seção:** Álgebra, polinômios e FFT — **Bullet:** **Floor sum.** — **Suspeita:** a recorrência com y_max = ⌊(a(n−1) + b)/m⌋ e soma = (n−1)·y_max − f(y_max, a, m, m − b − 1) não confere com o algoritmo usual de floor sum. — **Por quê:** para n = 4, m = 5, a = 2, b = 0, a soma é ⌊0/5⌋ + ⌊2/5⌋ + ⌊4/5⌋ + ⌊6/5⌋ = 1, mas a fórmula dá y_max = ⌊6/5⌋ = 1, (n−1)·y_max = 3 e f(1,2,5,4) = 0, resultando em 3; a versão padrão usa y = a·n + b, n ← ⌊y/m⌋, b ← y mod m e troca m com a.
- **Seção:** Álgebra, polinômios e FFT — **Bullet:** **Matriz de adjacência e passeios.** — **Suspeita:** a fórmula tr(A³)/6 para ciclos de comprimento 3 só vale sem qualificação para triângulos de grafo simples não dirigido. — **Por quê:** em grafo não dirigido cada triângulo aparece 6 vezes em tr(A³) (3 vértices iniciais × 2 sentidos), mas em grafo dirigido cada ciclo dirigido aparece 3 vezes (3 vértices iniciais), então o divisor correto é 3; laços e arestas múltiplas também alteram a contagem.
- **Seção:** Matemática de olimpíada e math.stackexchange — **Bullet:** **Rearrangement e Chebyshev.** — **Suspeita:** a afirmação de que, para qualquer f convexa, Σ f(a_i − b_σ(i)) é mínimo com ordens iguais e máximo com ordens opostas é ampla demais. — **Por quê:** para f(x) = e^x, a = [0,1] e b = [0,100], a ordem igual dá e^0 + e^{−99} ≈ 1, enquanto a ordem oposta dá e^{−100} + e^{−1} ≈ 0,368, então a ordem igual não é o mínimo; a direção clássica vale para f simétrica convexa, como |x| ou |x|^p.
- **Seção:** Matemática de olimpíada e math.stackexchange — **Bullet:** **AM-GM para otimizar.** — **Suspeita:** a fórmula do produto máximo por 3s não cobre n pequeno e pressupõe parcelas ≥ 2 (ou n ≥ 5). — **Por quê:** para n = 2, com pelo menos duas parcelas, o máximo é 1 (1·1), mas a fórmula com n mod 3 = 2 dá 2; para n = 3, com pelo menos duas parcelas, o máximo é 2 (1·2), mas a fórmula dá 3.
- **Seção:** Matemática de olimpíada e math.stackexchange — **Bullet:** **Coloração por IE de subconjuntos.** — **Suspeita:** a cota n ≤ 20–23 vale para a via de subset convolution, mas não para a inclusão-exclusão sobre arestas. — **Por quê:** a IE sobre arestas percorre todos os F ⊆ E e custa O(2^m); um grafo denso com n = 20 pode ter até 190 arestas, tornando essa via inviável mesmo com n dentro da cota.
- **Seção:** Otimização, programação linear e matroides — **Bullet:** Monge e SMAWK — **Suspeita:** a afirmação "Monge côncavo ⇒ f(k) convexa" depende da convenção adotada para matriz de Monge e do sinal da função, e o texto não fixa a convenção. — **Por quê:** na convenção usual (A[i][j] + A[i+1][j+1] ≤ A[i][j+1] + A[i+1][j]), a monotonicidade da argmin costuma vir acompanhada de convexidade da sequência ótima; para a desigualdade invertida ("côncava"), a conclusão se inverte, e alguns autores trocam os nomes. Sem definir a convenção, a direção afirmada pode estar certa ou errada.
- **Seção:** Otimização, programação linear e matroides — **Bullet:** LP inteiro e arredondamento — **Suspeita:** "arredondamento aleatório ... cobertura de vértices por 2-aproximação" não garante, por si só, uma cobertura viável: com x_u = x_v = 1/2 numa aresta, a aresta fica descoberta com probabilidade 1/4. — **Por quê:** a 2-aproximação clássica de cobertura de vértices vem do arredondamento por limiar x_v ≥ 1/2 (se x_u + x_v ≥ 1, ao menos um endpoint é ≥ 1/2); o arredondamento aleatório puro pode deixar arestas descobertas e precisa de uma etapa de reparo/derandomização para virar cobertura.
- **Seção:** Otimização, programação linear e matroides — **Bullet:** Mochila 2D / com conflitos — **Suspeita:** "conflitos bipartidos de peso → corte mínimo" só cobre o caso em que o problema é um independent set/vertex cover bipartido; com a capacidade da mochila presente, o corte mínimo sozinho não modela a restrição de soma global. — **Por quê:** o corte mínimo codifica conflitos binários, mas a capacidade é uma restrição de soma; a versão com pesos e orçamento é mochila com conflitos, NP-difícil em geral. O corte resolve quando não há orçamento (ou quando a capacidade entra apenas como penalidade lagrangiana, o que não dá solução exata direta).
